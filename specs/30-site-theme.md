## 1. Where we start (measured 2026-11-10)

The site was built locally with the action's own image
(`ghcr.io/actions/jekyll-build-pages:v1.0.13`), checked (`tools/check-site.js`,
7/7), and its pages looked at in a headless Chromium at 1400 × 1100.

- **The look is GitHub's, not ours.** `docs/_layouts/default.html` is the
  Primer theme's own layout with its footer replaced (10.6), and the stylesheet
  is Primer's. Pages read like a README on github.com.
- **No navigation.** A page's only link up is the `cog-lisp` title. A chapter
  reaches the other chapters only through the Previous · Contents · Next line
  at its very end, below a long listing; nothing shows the contents, or where
  the reader is in them.
- **The home page is thin:** a paragraph and four links. The site's
  `description` in `_config.yml` appears on no page.
- **The reference is hard to scan.** It is one 64 KB page with 360 or so
  entries:
  - its contents are a 21-line list that fills the first screen;
  - its four-column tables give a column to *Kind*, and squeeze *Call*, so long
    call forms wrap mid-form;
  - there is no way to find a name but the browser's own find.
- **The reference shows readers the maintainers' note:** its first paragraph
  says to "rebuild the image and run `./cog-lisp.sh tools/generate-docs.lisp`".
  The manual's pages keep the same note in an HTML comment.
- **Smaller things:** example output looks just like example source; no
  favicon; `anchor-js` 4.1.0 is fetched from a CDN on every page.

## 2. The approach, and what does not change

The owner was offered three ways (2026-11-10): (1) a layout, stylesheet and
script of our own, on the same build; (2) a ready-made theme such as
just-the-docs, through `remote_theme`, which needs front matter on every
generated page and fetches the theme at build time; (3) HTML generated by
cog-lisp itself, which would reverse 10.6's decision to have no converter of
our own. **The owner chose (1).**

What 10.6 built stays as it is:

- the site is still GitHub's own Jekyll build of `docs/`
  (`.github/actions/build-site`), checked by `tools/check-site.js`, built by CI
  and published by each release (`pages.yml`);
- the pages are still the generated Markdown, with no front matter; the theme
  is all in the layout, so a generated page needs nothing to take part in it;
- no new dependency: no remote theme, no plugin beyond those `github-pages`
  already runs, and nothing fetched from another site when a page is read (no
  web fonts, no CDN scripts);
- a page in `docs/` still never holds `{{` or `{%`. The layout uses Liquid,
  which is what a layout is for.

## 3. The look

**Dark only:** a near-black screen, text in a soft phosphor white, one warm
amber for links, and a phosphor green for what the terminal itself would draw
(the prompt, the comment marks, a program's output). It is meant to recall a
terminal, not to imitate one: no scanlines, no flicker, no all-green text.

**Typographic, and readable:**
- the structure is set in the system's monospaced font (headings, navigation,
  code, tables of names): `ui-monospace`, Cascadia, SF Mono, Menlo, Consolas,
  DejaVu Sans Mono;
- prose is set in the system's proportional font, at a measure of about 72
  characters, because a long paragraph in a monospaced face is slower to read
  (decision 1);
- headings carry LISP's own comment marks, in dim green: `;;;` before a page's
  title, `;;` before a section, `;` before a subsection, the way a cog-lisp
  file marks its own (`;;; docs.lisp -- ...`). They are drawn by the stylesheet,
  so the text and the anchors are unchanged.

## 4. Requirements

- **R-1. A layout of our own**, `docs/_layouts/default.html`, replacing
  Primer's. Every page has:
  - a header bar: the site's name as a prompt, `> cog-lisp` with a block
    cursor (still when the reader asks for reduced motion), linking home; and
    the site's sections: Manual, Built-ins, Releases, Source;
  - a sidebar listing every chapter of the manual, in order, and the
    reference, with the page being read marked (`aria-current="page"`). The
    layout lists the chapters from the site's own pages (those in `manual/`
    but its `README.md`), so a new chapter appears with no change here;
  - the page itself, in a `<main>`;
  - 10.6's footer: the release the site documents (`cog_lisp_version`), and
    links to the releases and the source.

  The sidebar numbers the chapters. Under 900 px wide it moves above the page
  and lists only the chapter being read (the manual's contents page lists them
  all), and the header's links wrap.
- **R-2. A stylesheet of our own**, `docs/assets/css/site.css`, plain CSS (no
  Sass, nothing for Jekyll to process). The layout links it and not Primer's.
  Its colors are custom properties on `:root`: a foreground's name starts
  `--fg-`, a background's `--bg-`, so the check of R-6 can find them.
  - Every foreground, the code's token colors included, has a contrast ratio
    of at least 4.5:1 (WCAG 2 AA) against every background.
  - Code is highlighted by the Rouge classes Jekyll writes (`p`, `nv`, `nb`,
    `nf`, `k`, `mi`, `s`, `c1`, `ss`, `o`, `no`, `sc`, `mf`, and the rest of the
    number classes); parentheses are dimmed, so the words carry the form. A
    token Rouge cannot read (`err`) is drawn as plain text, not flagged red.
  - Example output (a `text` block) is drawn as a terminal's screen, in green,
    so it never looks like source.
- **R-3. The reference is easy to scan.**
  - Its contents list is set in columns.
  - In its tables, Name and Kind never wrap, Kind is small and dim, and Call
    breaks only at spaces.
  - A filter box above the tables (from `docs/assets/js/site.js`) hides every
    row whose name does not hold what is typed, and every section left empty,
    and says how many names match. `/` puts the cursor in it; Escape clears it.
    The address can give it a first value (`builtins.html?q=string`), so a
    filtered view can be shared. Without script the page is as it is now.
- **R-4. The home page is a front page.** The site's `description` appears under
  its title, and its links are set as four blocks rather than a list. This is
  the layout's doing; `docs/index.md` is unchanged.
- **R-5. The reference's note for maintainers is a comment.** `builtins-markdown`
  (`tools/docs.lisp`) writes the note about generating the file as an HTML
  comment, as the manual's pages do. Its first paragraph for readers becomes
  "Every special form, derived form and built-in procedure, with its call form
  and what it does."
- **R-6. Script, anchors and icon.** `docs/assets/js/site.js`, loaded from the
  site, gives each heading with an id a link to itself (what `anchor-js` did)
  and builds the reference's filter. Nothing is fetched from another site.
  `docs/assets/favicon.svg` is the site's icon: a green prompt on black.

## 5. Acceptance criteria

`tools/check-site.js` gains these checks, so CI and each release run them:

- **AC-1:** every page links `assets/css/site.css`, and no page links Primer's
  `assets/css/style.css`.
- **AC-2:** every page has the header's four links and the sidebar; the
  sidebar links to every chapter of the manual and to the reference; and on a
  chapter, the link to that chapter is the one marked `aria-current="page"`.
- **AC-3:** no page loads a script or stylesheet from another site.
- **AC-4:** every `--fg-` color in `site.css` has a contrast ratio of at least
  4.5:1 against every `--bg-` color.
- **AC-5:** no text of the built reference (outside comments) mentions
  `generate-docs.lisp`.
- **AC-6:** the 10.2 and 10.4 suites still pass: the committed reference is what
  the generator writes, and no page holds Liquid syntax.
- **AC-7 (by hand, recorded here):** the home page, a chapter and the reference,
  in a browser at 1400 px and at 400 px wide, with the filter tried on the
  reference. Screenshots go with the change for the owner to look at.

## 6. Steps

One step: the layout, the stylesheet, the script, the icon, R-5's change to the
generator, the checks, and this spec's "as built". `CLAUDE.md`'s note on the
site names the theme's files.

## 7. Decisions for the owner

1. **Prose in a proportional font** (§3), or every word in monospace? Leaning:
   proportional prose, monospaced everything else. It is one custom property,
   `--font-prose`, either way.
2. **Accent colors:** amber links and green terminal marks, or a single color
   (all amber, or all green)? Leaning: the two, each with its own job.
3. **A code sample on the home page?** The generator could take one from an
   example. Leaning: not in this step; the theme first.

## 8. As built (2026-11-10)

Built to the leanings of §7, so the owner could judge them on the real pages;
the owner accepted them from the screenshots (2026-11-10).

- **Files:** `docs/_layouts/default.html` (rewritten), `docs/assets/css/site.css`,
  `docs/assets/js/site.js`, `docs/assets/favicon.svg`; `builtins-markdown` in
  `tools/docs.lisp` (R-5) and `docs/builtins.md` regenerated from it; the five new
  checks in `tools/check-site.js`.
- **The sidebar's chapters come from Liquid:** `site.pages` where `dir` is
  `/manual/` and `name` is not `README.md`, sorted by name. Each page's `title`
  is its first heading without the chapter's number (`jekyll-titles-from-headings`),
  so the layout writes the number itself, from the loop's index.
- **Checked** with the action's image (`jekyll-build-pages:v1.0.13`):
  `check-site.js` passes 12/12 (524 links in 19 pages; 15 foregrounds on 3
  backgrounds, the lowest 5.57:1, `--fg-tok-paren` and `--fg-tok-comment` on
  `--bg-raised`; body text on the page 13.74:1). On a copy of
  the built site broken five ways (a dim color, no current chapter, a CDN script,
  the maintainers' note, Primer's stylesheet) each new check failed, and only its
  own. The 10.2, 10.4 and 10.7 suites pass (19/19, 39/39, 434/434).
- **AC-7:** the home page, chapter 3 and the reference were looked at in a
  headless Chromium (`zenika/alpine-chrome`) at 1400 × 1000 and 400 × 900, and
  the reference with `?q=string` (46 of 530 names, every section without one
  hidden). Headless Edge on this machine writes no screenshot, so Chromium ran
  in Docker. Its fonts are DejaVu, not the system fonts a reader has.
